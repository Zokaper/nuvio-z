## Preserve during UI consolidation

Review `iosInstaller/ui/{app.js,steps.js,index.html,styles.css}`, `iosInstaller/app/` (Tauri 2 shell),
and `iosInstaller/core/src/` (desktop Rust installer) before designing another interface. Evaluate
current Tauri Android support and Android USB/JNI integration before committing to the migration.
Prefer a shared web UI and portable Rust workflow with Android-specific transport, secure storage,
permissions and callback adapters. Keep platform adaptation explicit. The temporary Java form is
proof scaffolding, not a second independent product. No UI consolidation is implemented yet.

Keep the successful native signing/install path, encrypted records/anisette/signing keys, explicit
certificate consent, cancellation/progress, and Debug/stable bundle separation. Apple credentials
and 2FA belong only in the app, never chat/logs. Diagnostic reports exclude account/device identities,
keys and raw sensitive SDK errors. Preserve desktop's merged Lockdown + remote-pairing
`NuvioZPairing.plist` and `NuvioZSigningKey.plist` contract for the iPhone's own refresh/update flow.

The Android proof uses the same isideload 0.4.6 / idevice 0.1.68 pins as desktop. Its independently
vendored isideload patch is Android-only: standard rustls certificate/hostname/signature checking
with WebPKI roots plus the bundled Apple CA, because Android's system verifier rejects extra roots
and Apple requires that CA. Generic HTTPS still initializes the official Android system verifier.
See `VENDOR.md` for provenance, licenses and exact two-file patch; do not weaken TLS or silently
propagate the experimental patch into production. Keep the existing paired app installed/data intact.
